### B. Notification "read then it comes back" fix (two layers)

Root cause: GitHub's `/notifications` is eventually consistent (~60s), and our
conditional cache was **not** invalidated on mark-read, so a `304` re-served the
just-read thread as unread; there was also no client-side guard during the lag.

| Layer | Change | Commit |
|---|---|---|
| Backend | **Invalidate the conditional cache on mark-read** (`_apply_read_to_cache`) so a `304` can't resurface a read thread; +3 tests | `a162a8c` |
| Frontend | **Recently-read guard** (`view.js`) — hides a just-opened thread (90s TTL, keyed by id) across refresh + WS push; a genuine re-mention is never suppressed; badge stays consistent | `03baed7` |
